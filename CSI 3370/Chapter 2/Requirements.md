Systems requirements = functional || non-functional

Functional requirements are activities that the system must perform.

Non-functional requirements are goals or system constraints. 

Every requirements falls under one of the categories that can be remembered using the acronym FURPS+
## FURPS+
Functional, Usability, Reliability, Performance, [[Security]] Requirements (that's a lot of requirements!)
### Functional
The only functional requirement in FURPS (that means everything else is non-functional).
### Usability
Who is the type of person the application is trying to cater to?
Consider:
- How technologically knowledgeable is the user?
- What service is the app providing?
- Can the app be used by people with disabilities?
- Is the app's color palette suitable?
### Reliability
- How often does the application need to be online?
- How will the application be handled if it goes down?
### Performance
- How quickly should the system respond to user input?
- How many users can the system handle?
### Security
- Hack the system to ensure there are no [[vulnerabilities]]. 
- How is data protected during storage and transmission?
- Will the system use [[Controls|MFA]] for logins?
### +
- Design constraints
	- Restrictions to which the hardware and software must adhere (i.e. screen size). 
- Implementation
	- The required programming languages, tools, and documentation. 
- Interface
	- How the system interacts with other systems. What file types are required to interact with those systems?
- Physical
	- How much power the system will consume, and what the size of the hardware is expected to be. 
- Support
	- How a system is installed, configured, monitored, and updated.
